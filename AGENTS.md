# BinderClip Agent Guide

- Keep changes separated by concern: protocol/features, networking, storage, and tooling.
- Update this file when an essential project convention, build command, or architecture detail changes. Keep it concise.
- macOS debug install: `./macos/debug-install.sh`.
- macOS production package: `./macos/package-release.sh`; it bundles Sparkle 2 and creates an ad-hoc signed universal ZIP, DMG, and signed appcast.xml using BWS secrets.
- macOS tests: `swift test --package-path macos/BinderClipMac`.
- Android tests: `./android/gradlew -p android test`.
- Android local Gradle verification uses Java 21 (`JAVA_HOME=$HOME/.local/share/mise/installs/java/21.0.2`); Java 26 fails Android SDK JDK-image transforms.
- BinderClip listens for direct encrypted TCP connections on port `39421`; one authenticated session carries text and one-at-a-time PNG/JPEG/WebP/HEIC images (up to 30 MiB) using AES-GCM frames and a four-chunk, 192 KiB cumulative-ACK media window. It uses a one-time QR invitation and has no legacy transport fallback.
- Either platform can host a chain: macOS runs an NWListener (`DirectTransport`), Android runs a `ServerSocket` (`DirectServer`) only while the app is in the foreground (`uiVisible`). Both expose "Create New Chain" (rotate group key + clear roster + show invite) and "Join Chain" (adopt the host's key via invite handshake). Android can be a client or host, never both at once.
- Clipboard classification is fail-closed: file URLs take precedence over TIFF/icons/text, but only supported image files are sent. All other files are ignored and must never be coerced into a filename string.
- The direct roster is shared with connected members. Removal is enforced by roster admission on future sessions; the group key is intentionally not rotated on leave/kick, so removal does not revoke data or keys already received. `createNewChain`/`startNewChain` rotate the key.
- Leaving a chain always clears local state and works offline: Android `leaveChain()` preserves the stable `device_id`/custom name (no identity churn); macOS `leaveChain()` clears peers/connections. Kicked/left devices return to the Create/Join onboarding empty state and stop auto-reconnecting.
- Auto-recovery keeps a joined chain connected across network changes: the macOS client persists a `HostTarget` (host ID + all invite endpoints + the group key) and reconnects as a returning member — sending a group-key-encrypted `hello` (no fresh invite) — on launch, on host-connection close, on path change, and on an 8s timer. Android clients already reconnect via `forceReconnect`/backoff on network callbacks; Android hosts now also accept returning members directly via encrypted `hello` and deduplicate a member's old socket on rejoin. A host that rotated its key (Create New Chain) rejects old-key reconnects, so the client must rejoin by QR.
- Android’s share target accepts supported images and text/URLs. It offers an interactive device picker to choose the target device (or all devices); when sharing a web URL (`http://`/`https://`), BinderClip sends an `openUrl` command that automatically launches the default browser on the target device. Automatic clipboard sync uses the app-owned root bridge for text/images only after KernelSU/Magisk grants `su`; it then grants BinderClip `READ_CLIPBOARD_IN_BACKGROUND` and revokes it when the toggle turns off. Otherwise it uses the user-enabled `ClipboardAccessibilityService` for text only. That service must remain clipboard-only: no window retrieval, gestures, or accessibility-event interpretation.
- Android background help may request the standard battery-optimization allowlist and open App Info for OEM Auto Start controls. Manufacturer-specific auto-start intents (Xiaomi/MIUI, OPPO/ColorOS, Vivo, Huawei/Honor, OnePlus/Realme) are attempted with `resolveActivity` checks and `try-catch` fallback to `ACTION_APPLICATION_DETAILS_SETTINGS`. Do not hardcode private intents without fallback.
- On macOS, list unresolved Launch at Login, Local Network, and (macOS 15.4+) denied Clipboard Access in the menu. Local Network privacy is tracked reliably in distribution only with an Apple-issued signing identity; do not claim a denied/allowed state before Network.framework reports it.
- Store CI credentials in BWS first; GitHub Actions should use only the BWS access token to load project secrets at runtime. Do not commit or print secret values.
- Do not revert unrelated worktree changes.
